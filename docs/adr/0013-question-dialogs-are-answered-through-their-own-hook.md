# 0013 - Question dialogs are answered through their own hook; hq types nothing into a dialog

`hq answer` and the supervisor's `answer` tool answer an agent's question dialog (AskUserQuestion) on the user's word, while the dialog stays open and answerable at the agent (#80, #90). The answer reaches Claude through the dialog's own hook, the way a message reaches it through the Stop hook (ADR 0012): hq injects a second PermissionRequest hook, matched to AskUserQuestion, with a timeout of a day, which holds while the dialog is open and prints the answer hq leaves in the agent's inbox as its decision. An answer is an allow whose updated input is the tool's input with `answers` added; a cancel is a deny with `interrupt`, which ends the turn as Esc does. The hook ends by itself, with no decision, once the dialog's state file moves on; hq writes the decision whole on the host, so the hook only copies it. Verified with Claude Code 2.1.302 by the spike #89 ([verdict](https://github.com/rkrysinski/hq/issues/89#issuecomment-6230967612)): PermissionRequest honours the answers, PostToolUse carries them about 10 ms later, the dialog is drawn and answerable at the terminal while the hook holds (up to 640 s), and a timeout of 86400 is honoured, the dialog staying open when it is reached. Re-verified with hq's own hooks in #90: the hook that reports the dialog and prints its notification does not keep Claude from taking the held hook's answer.

**Prerequisite in the sbx template.** The template's own PermissionRequest hooks must not answer AskUserQuestion: they print nothing for it. Claude runs the PermissionRequest hooks side by side and takes the first decisive result; for AskUserQuestion it reads a bare `allow` as no decision and stops there, so a hook that answers it ahead of hq's makes Claude ignore hq's answer. During #89 and #90 the template the agents ran had an auto-approve hook that gave that bare allow for every request, AskUserQuestion included; it was changed to stay silent for AskUserQuestion. A sandbox keeps the template it was created with, so a sandbox created before its template changed needs recreating.

## Considered Options

- **Type the keys through tmux** (the fallback #80 decided in advance): needs a reader of the dialog's screen to know where the cursor is and which step it shows, which #68, #70 and #77 showed to cost; and keys sent as the screen changes can answer a dialog that opened meanwhile. Set aside once the template change was taken.
- **PreToolUse instead of PermissionRequest**: Claude draws no dialog while a PreToolUse hook holds (#89, case 1c), so the user at the terminal would see a spinner in place of the question.
- **Answer from the hook that reports the dialog**: its standard output carries the dialog's notification, which Claude reads only when the hook ends, so holding there would hold the notification back; a hook of its own keeps the notification as it was.
- **Answer MCP elicitations the same way**: Claude runs the Elicitation hooks before it draws the form, so while one holds the user sees no form (#89). Moved to #95.

## Consequences

- hq types nothing into a dialog: an answer reaches Claude only as a hook's decision. Permission prompts, MCP elicitations and dialogs of Claude's own stay the user's, at the agent. Amended by [ADR 0014](0014-dialogs-of-claudes-own-are-answered-with-keys.md): a dialog of Claude's own, which fires no hook, is answered with keys, once a capture shows the dialog the user read; a list of Claude's own that scrolls stays the user's.
- One more kind of file crosses into the sandbox besides messages: the answer, a decision hq encodes on the host from the dialog's own questions and the user's choice (labels, or free text stripped and capped as a message is). The hook never evaluates it.
- A hook may hold for as long as a dialog is open, up to a day; it does not hold Claude back, since the dialog stays answerable at the terminal, and it polls a file a few times a second. Claude does not stop it when the dialog closes (#89, case 2d), so it watches the state file and ends by itself; an answer is named for the dialog's report, so the hook of another dialog never takes it.
- "The file was taken" is not "the answer landed": `hq answer` waits for the dialog to close and compares what Claude reports it got with what was sent. A dialog that does not close names the likely cause, a template whose own PermissionRequest hook answers AskUserQuestion. Since #128 `hq answer` checks the prerequisite first and refuses, naming the template's hook, when one answers AskUserQuestion (design §3.4, Answers). Such a dialog stays the user's at the agent: Claude took the template's answer when it opened it.
- Agents launched by an older hq have no such hook; `hq answer` refuses them with the remedy (a relaunch), as `hq send` does for agents whose hooks ignore the inbox.
