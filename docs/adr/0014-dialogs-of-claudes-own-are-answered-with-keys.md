# 0014 - Dialogs of Claude's own are answered with keys, once the screen shows the dialog that was read

Amends [ADR 0013](0013-question-dialogs-are-answered-through-their-own-hook.md), whose consequence "dialogs of Claude's own stay the user's" no longer holds for most of them.

`hq answer` and the supervisor's `answer` pick an option of a dialog Claude Code draws of its own in place of its prompt box, on the user's word, as they answer a question dialog (#120): "Change effort level?" after `/effort`, "Switch model?" after `/model NAME`, and the question at a session's start about the default permission mode. The question whether to trust the folder is not among them: with Claude Code 2.1.304 it comes before any of Claude's hooks runs, so the agent is `starting` and hq sees no dialog to answer (QA of #120); it is answered at the agent, as before. Such a dialog fires no hook (#29, #66), so no hook can carry the answer as ADR 0013's does; hq presses the keys a person would, through tmux, in the agent's pane. It presses nothing until a fresh capture of the pane shows the dialog the user read: the dialog's id gives the moment hq first saw it, and that moment's record on the agent's window names it by a fingerprint of its title and text (`@hq_dialogseen`, design §3.4), which the capture must give too. It then moves the `❯` to the option one `Down` or `Up` at a time, each once a new capture shows the `❯` moved and the same dialog, presses `Enter` on it, and returns once the agent has left that dialog. A dialog that changes while the `❯` moves, or a `❯` that does not move within 2 s, gets no `Enter`: nothing is picked. The rule reads the real dialogs of Claude Code 2.1.300 and 2.1.304 (`internal/state/testdata/screen-own-*`); with 2.1.304 in the sbx template's managed settings (#120) `Down` and `Up` redrew the `❯` within 0.1 s, wrapping round at the ends, `Enter` picked the option under it, and a digit picked its option at once.

A list that scrolls past what its screen shows, the picker of `/model` with no name (a `↓` before an option, `… +3 models` below), is not answered: the numbers it shows are not the whole list's, the cursor scrolls the list, and `Enter` there sets the default for new sessions while `s` keeps it to the session. `/model NAME` asks "Switch model?" instead, which hq answers. A dialog of Claude's own takes one option: no free text, and no cancel, which would be Esc, whose effect differs from one such dialog to the next; where a dialog has a way back, it is one of its options ("No, go back").

## Considered Options

- **Keep them the user's** (ADR 0013): the release supervisor sets `/model` and `/effort` on each agent before its first turn, where both take effect without a dialog; any later change needed a person at the agent.
- **Set the level at launch** instead: Claude Code 2.1.304 takes `--effort` and `--model` for a session, and keeps the level a change saves as the default for new sessions in its user settings (`modelSettings.<model>.effortLevel`, which a sandbox image could carry); neither opens a dialog, but both hold only from the session's start: a change later in the session still asks. No environment variable for the effort was found (the binary was searched; inconclusive, it may be packed).
- **The option's digit**: one key, no `❯` to follow, but options past 9 have none, the start dialogs show no numbers, and the key acts before hq can see where it would land. The arrows, each seen to land, are checked before anything is picked.
- **All the keys at once, then a capture**: Claude takes several keys in one `send-keys`, but an `Enter` sent with them would pick whatever the `❯` reached, a dialog that opened meanwhile included.

## Consequences

- hq types into the pane of an agent for a dialog: only the keys `Down`, `Up` and `Enter`, by their tmux names, never text, and only while a capture shows the dialog the user read. ADR 0013's answers through the hook are unchanged; permission prompts, MCP elicitations and a list of Claude's own that scrolls stay the user's, at the agent.
- No hook is needed, so an agent launched by an older hq is answered too.
- What Claude did with the option is not checked: no hook reports it. The option under the `❯` was checked before `Enter`; that the agent left the dialog is checked after it, within 5 s.
- The id names the dialog by when hq first saw it during the agent's current report, and the record keys it by its title and text: a dialog answered at the agent and opened again the same, with no look of hq's in between, keeps its id, and an answer meant for the first lands on the second. It is the same question, and the same choice is then made.
- The question at a session's start about the default permission mode is answered by the same rule, read on its 2.1.285 capture; with 2.1.304 it was not seen live in #120.
- The rule rests on the screen: a Claude Code that draws these dialogs otherwise is caught by its captures (`tools/capture/`), as every screen rule is.
