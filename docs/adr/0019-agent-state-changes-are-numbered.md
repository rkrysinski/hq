# 0019 - Agent state changes are numbered

`hq wait --since`, and every supervisor loop built on `next_since`, decided whether an agent entered a state after a moment (#166). Every process derived that moment from the agent's records, case by case (a rewind is its first rest plus 2 s, an end the earliest of three times plus 1 s), and a look returned only what entered at least 250 ms before it began, so that what it could not see yet fell to the next call. It depended on clocks (the sandbox's and the host's, which jumps after the laptop sleeps), its rules had to agree in every process, the 250 ms delayed every result, and a paged `hq read` tied its pages to a reply through the same moments.

Now every change of an agent's state is numbered: by the number the host's one counter gave the event that made it (ADR 0018: one lock and one counter for the state directory, never reset, never used twice across tmux servers, restores and repositories). This ADR adds no counter of its own; it adds the public half.

- **Two numbers per agent.** `state_seq` is the number of the event at which the reducer's state, or the dialog the agent is at, last changed: a report that leaves both as they were moves it not, and a new dialog while the agent still needs input does. `completion_seq` is the number of the event that ended its last completed turn: a turn end the hook reported as `done` or `question`, a supervised turn and a turn Claude started itself included; and a turn Claude owed and did not take counts as completed, numbered by the screen's event that decides it does not come (`TurnNotTaken`, after a turn end the hook reported and kept `working` for background work), as the operator decided on #166. A stop blocked to deliver a message is no completed turn, nor is a session that just started, a resumed or restarted conversation, or a turn the user ended at the agent. Every agent whose state hq shows from its journal has a `state_seq`; `completion_seq` is null before its first completed turn. An agent with no event behind its state has neither: an outdated agent, whose journal hq does not read, one `starting` before its journal holds an event, one `ended` whose journal cannot be read, and one killed while a `hq wait` watched it.
- **The cursor.** `next_since` is an opaque text, passed back as given, that stands for a number N such that the look that gave it saw every change numbered up to N; a `hq wait` returns no change numbered above its own N. So consecutive calls return every change once and none twice, with any number of hq processes looking at once. N is not the highest number the look saw: a look reads each agent's journal in turn, and an event another process numbers for an agent the look has already read, before it reads the next, is numbered at or below that next read's counter without being seen. N is the lowest counter of the look's last reads of the agents' journals, or the counter before the look listed the agents when that is all it can vouch for (no journal read, one that could not be, an agent that appeared while it looked). The cursor of `hq read`, `hq send` and `hq answer` is that one agent's (the counter of its read, or the counter just before the message or the answer is left, so what the agent does with it counts as after it); a watch takes its cursor from `hq wait` and `hq ls --json` alone. A cursor above the counter, which hq never gave (as after a lost state directory), is refused, saying to take a new one from `hq ls --json`.
- **`hq wait --since CURSOR`** returns every agent it waits on whose `state_seq` is above the cursor, at most its own N, and whose state is `done`, `question`, `needs input` or `ended`, with no settle time. It still returns with the look after the one that found a change, so agents that finish together come back together (#116): about 250 to 500 ms after the change is in the journal. An agent killed while waited on, or ended with an unreadable journal, is returned as `ended` by the call that saw it before, since it has no number to compare.
- **Moments stay.** `--since` also takes a moment (RFC 3339, as an older hq printed `next_since`, so a supervisor started before the upgrade keeps working) or a duration back from now, for good: both are compared with the time of the change and are approximate by nature, and the result always carries a cursor, so the loop that follows is exact.
- **Paged read.** `hq read --offset N --since CURSOR` refuses the page once the latest turn end is numbered above the cursor; with a moment it compares the turn end's time, as before.
- **A relaunch is a change.** `hq restore` and `hq sandbox restart` append the relaunch, which makes the agent `starting` and so moves `state_seq`; `completion_seq` stays, a cursor taken before still works, and no number is used twice (the operator's decision on #166).

## Considered Options

- **Moments derived from records** (before): two clocks, a settle delay and per-case rules every process has to share.
- **A number per agent**: the cursor would have to carry one number per followed agent; a host-wide number orders all agents with one.
- **Timestamps from one clock**: the host's clock still jumps after sleep, and the sandbox's events would have to be dated again on ingest anyway.
- **The highest number the look saw as the cursor**: loses a change another process numbers for an agent the look has already read.

## Consequences

- The moments derived for `hq wait` ("Entered after a moment") and its 250 ms settle time are gone; a call with a cursor uses neither the moment an agent entered its state nor any settle time. That moment stays for `AGE` and for the moment form of `--since`: numbers order changes, times measure them.
- `next_since` is a string where it was a time; the descriptions of the supervisor's tools and the server's instructions say to pass it back as given.
- `completion_seq` is a reliable "this turn finished" for later features, such as a seen or unseen `done` in the list (#167). `hq send --wait` (#170, return when the turn the message started ends) returns on what `hq wait` returns instead: a `state_seq` above the number of the delivery that took the message, since a turn the user ended, a dialog, an end and a queued prompt move the two numbers apart.
- Returning a change that left an agent where it was before (an agent back at `done` once a dialog of Claude's own closes) is a change like any other: `state_seq` moves, and `hq wait` returns it once.
